# AGENTS.md — python_mini_metro

## What this is

A Python 3.13 `pygame-ce` implementation of Mini Metro: optimize how many passengers your metro system delivers. Human and programmatic play are both supported; a Gymnasium player-equivalent pixel environment plus Stable-Baselines3 training/evaluation scripts (`scripts/train_rl.py`, `scripts/evaluate_rl.py`) make RL training a first-class purpose.

The recursive playtest loop runs on Node ≥ 20.6 against the built ignored `/.civ-engine-pin/` checkout described by `scripts/civ-engine-pin.json`; it never relies on or mutates `../civ-engine`. Keep workflow guidance rooted in the repo's existing Python commands and root-level documentation.

This repo's own rules live in [docs/policies/local-rules.md](docs/policies/local-rules.md). They add repository constraints consistent with the Fleet Orchestration Policy below.

### Fleet Orchestration Policy

Deliver the requested outcome with verified correctness, coherent architecture and minimal necessary complexity. Optimize useful progress, not agent count, code volume or maximum reasoning. Adapt rigor to risk. This policy grants no new permissions or capabilities. [R1]

**Roles.** Only an explicitly designated agent coordinates; each scope has one accountable integration owner. The coordinator owns planning, dependencies, shared interfaces, architectural consistency, integration and acceptance. It reads only what assignments, acceptance or its own trivial change need, accepts or rejects inspected handoffs, and delegates all but trivial changes that cost more to delegate (owner directive, 2026-09-23, superseding 2026-09-05). Trivial means at most about 20 changed lines of docs, config or an integration fix, no R10 high-risk change, product logic, migration, security or trust-boundary code; the same gates, review and worktree rules apply. [R2]

Workers own bounded outcomes and local implementation decisions. Each worker, reviewers included, chooses and dispatches its subagents within budget: none for a small task, while remaining accountable for their work (owner directive, 2026-09-23). Threads follow deliverables, not permanent departments; no recursive manager hierarchies. [R3]

**Plan and delegate.** Inspect instructions, code, docs, tree state and active tasks; set outcome, non-goals, acceptance criteria, dependencies and verification; settle ambiguity with evidence and reversible defaults. Use the simplest delegation: subagents for bounded investigation, independent judgment or localized changes, separate threads for substantial independent changes. Agree shared contracts before parallel work; no duplicate or blocked work. Assignments name owner, outcome, context, dependencies, contracts, base revision, workspace, scope and exclusions, verification, resource limits, handoff, and read-only or implementation. Change model and reasoning defaults only through supported controls, on evidence. [R4]

Size the team continuously (owner directive, 2026-09-15): widen when one worker holds the critical path and independent work waits; narrow when workers contend for files, ports or CPU. Account for shared services, databases, ports and compute: serialize same-file edits in one tree, duplicate gates and unshareable resources. Run one expensive gate at a time; choose other work around it. [R5]

**Session size** (owner directives, 2026-09-23 and 2026-10-22). Sessions run long: take new requests as separate assignments in the same session, and never hand off to a successor session to shed context; auto-compaction carries the session. Split tasks expected to exceed about 200k context tokens into milestones within that budget, each committed and merged to main once green. Milestones are task boundaries; harness compaction never justifies wrapping up or handing off. No unattended "don't stop until done" loop without milestone commits. Mechanical subagents use lower effort or a smaller model; reviews and their subagents keep the review runbook's pins. Per-item model calls are one-shot, never full agent sessions. [R6]

**Coordinate safely.** Use available capabilities; assume no visibility into other chats, shared memory, automatic messaging, workspace isolation or persistent monitoring. If spawning is unavailable, work directly or hand off explicitly. Beyond a trivial read, each session or agent defaults to its own worktree to isolate concurrent edits. Serialize overlapping writes only when no worktree is available, and say why. Finish each bounded increment in its session: merge to main, push, then `git worktree remove`. Remove completed task-owned branches and unneeded temporary files; explicitly transfer ownership and locations of still-needed resources. Report any merged worktree left and its location as a defect. Never overwrite or discard another participant's work. Track delegation to completion, cancellation or handoff; release only owned resources without losing work. On resumption, first inspect surviving worktrees, artifacts and task status; recover what exists and preserve unfinished work, assuming no worktree, transcript or shared memory survived until checked. Periodically spawn a fresh subagent to review the whole effort for fundamental flaws, unnecessary detail, hard problems or loops; reassess from its findings. Propagate contract changes; revalidate stale information. Distinguish requirements from behavior, prepared from dispatched work, observations from assumptions, and implemented, verified, reviewed, integrated and blocked work. At handoff or interruption preserve goals, acceptance criteria, todos, owners, resource locations, outcomes, revisions, checks, results, evidence, risks, blockers, decisions, open issues, next steps and integration needs, excluding secrets and needless private data. Workers act autonomously in scope; escalate cross-task interfaces, persistent formats, security boundaries, major dependencies and scope changes to the coordinator for resolution within the approved mandate. ## Gates

- Python is pinned to 3.13 by `environment.yml` (`python=3.13`, conda env `py313`) — the env the Python gates below run in. Three places carry their own copy of that number and are bumped with it: `pyproject.toml` (ruff `target-version`), CI (`.github/workflows/test.yml`), and the lockfile re-resolution (`uv pip compile --python-version 3.13`).
- Every code or behavior change: full unit suite in `py313` — `python -m unittest -v`.
- Any change under `test/`, `scripts/` or `src/`: also run `python scripts/run_without_rl_extras.py -m unittest`. It hides the RL extras, which a development machine has and CI's `build` job does not, so a test that reaches for torch, Stable-Baselines3, sb3-contrib, tensorboard or Pillow without skipping is caught here instead of in CI. It hides those five roots and nothing else, so it says nothing about any other difference between a laptop and a runner. A test that skips itself in `build` must be named in the `rl-smoke` module list, or it runs nowhere.
- Changed Python files: `python -m ruff check <files>` and `python -m ruff format --check <files>`.
- Close each validated unit of change by writing the formatting in before you commit: `python -m ruff format <files>` then `python -m ruff check --fix <files>`. If either edits a file, re-run the unit suite — a formatting pass is a code change. No commit hook catches this any more, so an unformatted commit is the author's to prevent.
- Full-repo `ruff check .` and `ruff format --check .` are required for lint/format cleanup tasks; if they fail on known baseline drift during unrelated work, report that honestly and keep changed files clean.
- Loop machinery: under the trusted canonical npm/Node bootstrap, `npm test` is the guarded fixed full `node --test` contract suite and accepts no forwarded package-script arguments; focused development runs use direct `node --test <files>`. The setup and guard mains require `NODE_OPTIONS` to be unset or empty and `process.execArgv` to be empty before their own effects. Each guard checks its setup-exclusive verification lease before and after verification and holds it through child completion, but the token lock remains advisory against out-of-band filesystem tampering while the child runs. CI (`.github/workflows/test.yml`) dogfoods isolated setup on Ubuntu and Windows, then runs those contracts, a clean recursive pass, `python -m unittest -v`, and the Windows RL smoke job — local validation is intentionally stricter on changed Python files.
- Dependency audit gate (any change to `requirements*.txt` or `environment.yml`): re-resolve the hash-pinned lockfile — `uv pip compile requirements.txt --python-version 3.13 --universal --generate-hashes --output-file requirements-locked.txt` (same pattern for `requirements-rl.txt`) — then run `pip-audit -r requirements-locked.txt --disable-pip`; a new CVE is a blocker; note the result in the commit message.
